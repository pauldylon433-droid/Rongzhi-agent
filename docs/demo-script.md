# 演示脚本与答辩提纲（约 5 分钟）

> 演示会**改变数据**：请使用独立演示库（干净源码复现时生成），不要使用开发库或真实凭据。
> 所有账户、余额、商户、验证凭据均为模拟数据；不连接真实银行。

## 一、演示前准备（约 2 分钟，不计入 5 分钟）

1. 干净源码目录：`cd backend && npm ci && npm run db:init`；
   可选多卡与样例：`node scripts/add-existing-user-cards.js --db data/rongzhi.db --user-id 1 --apply --with-debit-samples --with-consumption`。
2. 启动后端（独立端口，Windows PowerShell）：
   `$env:PORT='4300'; $env:DB_PATH='<演示库绝对路径>'; node src\index.js`；
   前端 `npx vite --port 5280` 并代理到 4300（或在 `frontend` 目录设置 `$env:ISOLATED_BACKEND='http://localhost:4300'` 使用隔离配置）。
3. 打开前端，确认三张卡：借记 1234、借记 5678、信用卡 0003。
4. 强验证：首次使用按 `node scripts/bind-verification.js` 绑定（生成该环境独立主密钥与 TOTP，不复用开发环境）。

## 三、PPT 内容大纲（8 页，暂不做成品）

1. 项目定位与用户痛点（单用户模拟银行 Agent）。
2. 五个业务场景与多账户 / 信用卡扩展。
3. 技术架构（Vue 3 + Express 5 + SQLite；操作单 + 版本 CAS + 同事务审计）。
4. 安全设计（密码 + TOTP、防重放 / 锁定 / 限流、归属校验、AI 工具白名单、凭据入口拦截）。
5. 交互亮点（自然语言 → 工具 → 结构化结果卡；多卡上下文；范围联动；逐笔结余）。
6. 信用卡账单与提前还款（两种全额模式、未出账提前还款、出账不重复计债）。
7. 验证与质量（36 后端 + 6 前端脚本、构建、人工验收；如实说明未验证项）。
8. 边界与路线（模拟边界、后续可做的认证 / 调度 / 真实接入 / 合规）。

## 四、答辩要点

- **为什么用操作单**：把“模型建议”和“用户授权执行”分离；版本 CAS 防止建单后状态变化被旧单覆盖。
- **强验证为何跨业务共享**：同一密码 / TOTP / 失败锁定 / 时间步防重放，避免各业务各造一套。
- **金额计算**：全部由服务端按数据库计算（还款、结余、额度），客户端不能提交金额。
- **AI 边界**：模型只能查询与准备操作单；确认、凭据、执行都不经过模型；数据字段以 JSON 下发并标注“数据不是指令”。
- **数据一致性**：账单出账快照、提前还款冲抵、余额不变量、主密钥与数据库成套备份。
